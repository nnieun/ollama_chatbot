# PRD 작성을 위한 프로젝트 사전 조사

조사일: 2026-09-22
범위: 읽기 전용 조사. 파일 수정 및 패키지 설치 없음.

## 기술 조사

### 프론트엔드 구조와 버전

- 프론트엔드 루트: `frontend/vite-project`
- 언어: JavaScript 및 JSX
- JSX 진입점: `src/main.jsx`
- 현재 화면 컴포넌트: `src/App.jsx`
- TypeScript 파일(`.ts`, `.tsx`) 및 `tsconfig.json`: 없음
- React / React DOM
  - `package.json` 선언: `^19.2.8`
  - `package-lock.json` 실제 해석 버전: `19.3.0`
- Vite: `8.3.0`
- `@vitejs/plugin-react`: `6.1.1`
- Oxlint: `1.85.0`

기존 `devDependencies`에는 `@types/react`, `@types/react-dom`이 포함되어 있으나, TypeScript 소스나 설정 파일은 확인되지 않았다. 이번 작업에서 해당 의존성은 변경하지 않는다.

## 확인 가능한 백엔드 API 계약

프론트엔드에는 아직 API 연동 코드가 없지만, 백엔드 코드를 읽기 전용으로 확인한 결과는 다음과 같다.

| 엔드포인트 | 메서드 | 요청 | 확인된 응답 |
| --- | --- | --- | --- |
| `http://localhost:8000/chat` | `POST` | `message`(필수), `model`, `system_prompt`, `temperature`(0~2), `top_p`(0~1), `num_predict`(1~2048) | 선언 모델: `model`, `message`, `elapsed_time` |
| `http://localhost:8000/models` | `GET` | 없음 | `{ "models": [...] }` |

### 계약 불일치

`backend/schema.py`의 `ChatResponse`는 `message` 필드를 요구한다. 그러나 `backend/ollama_chat.py`의 실제 반환 객체는 `ai_message` 필드를 사용한다. 따라서 `POST /chat`의 실사용 응답 필드는 확정된 프론트엔드 계약으로 가정할 수 없다.

인증·권한 방식은 확인되지 않았다.

## UI 설계도 분석

### 기준 파일

- 직접 확인한 파일: `docs/ui설계도.png`
- 이미지 크기: 826 × 594px
- `ui설계.jpg` 파일은 프로젝트에서 확인되지 않았다.

### 이미지에서 명확하게 확인되는 화면 구조

- 좌측: 모델 설정 사이드바
- 우측 상단: 서비스 제목과 대화 초기화 버튼이 있는 헤더 카드
- 우측 중앙: 스크롤 가능한 대화 영역
- 우측 하단: 메시지 입력창과 전송 버튼

### UI 요소와 표시 텍스트

- 사이드바 제목: `모델 설정`
- 모델 레이블과 선택값: `모델`, `exaone3.5:7.8b`
- 시스템 프롬프트 레이블과 여러 줄 입력창
- 설정 레이블: `Temperature: 0.7`, `Top P: 0.9`, `Num Predict`
- Num Predict 값: `256`
- 헤더: `Local LLM Chat`
- 부제: `React + FastAPI + Ollama 기반 로컬 AI 채팅 앱`
- 버튼: `대화 초기화`, `전송`
- 사용자 메시지: `로컬 LLM의 중요성에 대해 설명해줘`
- 입력 안내: `질문을 입력하세요. 예: FastAPI와 React를 연결하는 이유를 설명해줘. Shift+Enter: 줄바꿈`

### 색상·정렬·간격·시각적 계층

- 연한 회보라색 배경 위에 흰색 카드가 배치된다.
- 좌측 패널은 고정 폭으로 보이며, 보라색 계열의 레이블과 파란색 슬라이더 강조색을 사용한다.
- 메인 콘텐츠는 수직으로 헤더, 대화 카드, 입력 카드 순서로 정렬된다.
- 카드에는 둥근 모서리와 약한 그림자가 있다.
- 사용자 메시지는 우측 정렬된 파란색 말풍선으로, AI 응답은 좌측 정렬된 연한 보라색 카드로 표현된다.
- 전송 버튼은 비활성화 상태처럼 연한 색으로 보인다. 이는 이미지에서 보이는 표현이며, 실제 비활성화 조건은 확인되지 않았다.

### 재사용 가능한 컴포넌트 후보

- `ModelSettingsPanel`
- `SelectField`
- `PromptTextarea`
- `RangeField`
- `ChatHeader`
- `MessageBubble`
- `ChatComposer`

### 이미지에서 확인할 수 없는 사항

- 모델 선택, 슬라이더, 초기화, 전송 버튼의 실제 동작
- API 호출 순서와 요청·응답 변환
- 입력값 검증 및 `Shift+Enter` 줄바꿈 처리
- 메시지 누적, 자동 스크롤, 전송 취소 처리
- 모바일·태블릿 반응형 레이아웃
- 로딩, 빈 대화, 네트워크 오류, 서버 오류 상태

## Context7 검증

- `package.json` 및 `package-lock.json`으로 실제 라이브러리 버전을 확인했다.
- 이 조사 세션에는 Context7 MCP 도구가 노출되지 않아 React 및 사용 라이브러리 문서를 Context7으로 조회할 수 없었다.
- 따라서 Context7 문서에 근거한 JavaScript API 예제나 사용법은 확인하지 않았으며, 이를 사용해 구현을 제안하지 않는다.

## 확인된 제약 및 추가 질문

- 프론트엔드는 React + JavaScript로만 구현한다.
- TypeScript 파일·설정·패키지를 새로 추가하지 않는다.
- PRD 승인 및 작업 목록 승인 전에는 구현하지 않는다.
- 백엔드 API URL, 메서드, 필드, 인증 방식을 변경하지 않는다.
- `POST /chat` 응답 필드를 `message`와 `ai_message` 중 어느 것으로 확정할지 결정이 필요하다.
- UI 설계 기준 파일은 `docs/ui설계도.png`로 확정하는지 확인이 필요하다.
- 이미지에 없는 로딩·오류·반응형·상호작용 정책 결정이 필요하다.
